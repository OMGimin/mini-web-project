## 실제 서비스 연결 검증

`scripts/verify-live-ai.py`로 Spring → FastAPI → 가짜 모델 → PostgreSQL 흐름을 검증했습니다. 최신 실행의 가상 재판 6~9번에서 아래 네 시나리오가 모두 통과했습니다.

1. 정상 진행: 진술·변론 확정, 확정 후 수정에 따른 준비 해제와 재확정, 공방 4회, 투표, 최종 의견 저장.
2. 공방 생성 실패: 실패 상태에서 진행 정지, 생성자 재시도로 복구.
3. 공방 생성 10초 지연: 생성 대기를 관찰하고 공방 완료 전 투표를 열지 않음.
4. 최종 의견 생성 실패: 실패 상태 유지, 재시도 후 결과 저장.

생성 순서 A → B → B → A, 이전 공방 전달 개수 0 → 1 → 2 → 3, 최종 의견 입력의 공방 4개 및 양측 원진술 포함, 관전자 투표 입력 제외를 확인했습니다. 책임 비율 합계 100, 승자 없는 결과, 판단 근거 저장도 확인했습니다. 테스트 서버의 50:50은 검증용 응답이며 실제 모델의 판단이나 제품의 고정 비율이 아닙니다.

브라우저에서는 결과의 비율·근거·실천 제안, 생성 중 표시, 새로고침 후 생성·실패 상태 복구, 실패 시 항상 보이는 재시도 버튼과 클릭 후 진행을 확인했습니다. 재판 생성자가 아닌 사용자의 재시도 요청은 HTTP 403을 확인했습니다.

## 미실행 및 남은 범위

- 실제 모델의 사건 이해, 상호 반박 품질, 비율과 근거의 일치, 편향 평가는 미실행입니다. 비용 범위를 승인받은 뒤 별도 평가해야 합니다.
- Docker 데몬을 실행하지 않아 이미지 빌드와 Compose 전체 구동은 미실행입니다. 이번 연결 검증은 로컬 프로세스로 수행했습니다.
- 여러 Spring 인스턴스 동시 운영, 실제 인증 도입과 외부 배포는 이번 범위에 포함하지 않습니다.
- 로컬 미리보기는 테스트 서버를 사용하며 재판 시간도 검증용으로 단축되어 있습니다.
